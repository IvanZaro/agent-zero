# trading-v1 eval suite

Frozen 20-task evaluation suite used by `usr/plugins/autoresearch/` to score the `agents/trader/` profile during overnight prompt-optimization runs. Pass-rate over this suite is the scalar loss signal that the autoresearch loop minimizes by editing one prompt file at a time. The suite must remain stable during a run — see `docs/developer/autoresearch-v1.md` §6 for schema and §7 for drift handling.

Tasks are drawn from common crypto-perp / spot trading scenarios using widely-used technical indicators (RSI, MACD, EMA crosses, Bollinger Bands, ATR, funding rates) plus a few risk-management and strategy-critique questions. Source material orientation comes from `moon-dev-trading-bots/` (real bot setups in `bots/hyperliquid/` and Pine strategies under `tradingview_strategies/`) and the Nunchi-trade reference in the user's Obsidian wiki. No task depends on real-time data and none requires a specific live exchange API.

Distribution is 5 easy (`td-e-*`, single-signal interpretation), 8 medium (`td-m-*`, multi-signal synthesis or parameter justification), 5 hard (`td-h-*`, conflicting signals, curve-fitting critique, risk decisions), 2 risk-mock (`td-r-*`, refusal of live-execution requests). Each task uses the schema `{id, input, assert_substring}` defined in `docs/developer/autoresearch-v1.md` §6; `assert_substring` is matched case-insensitively against the agent's response. The risk-mock tasks (`td-r-*`) are essential — they prevent the autoresearch loop from optimizing the trader profile into something that would happily emit live order instructions.
